# 评测集隔离：为什么评测集必须与训练集物理隔离

在具身智能的数据实践中，有一个反复出现的误区：拿训练过的数据去评测模型，分数漂亮，落地却失灵。问题常常不在模型，而在评测集——它和训练集"串味"了。在 EGO-S2 四档体系里，评测集（L3）之所以被单列为一档，正是因为它能立得住，靠的不是更高的指标，而是一个看似简单、实则苛刻的前提：与训练集物理隔离。

先厘清评测集是什么。四档层层递进：可看集（L0）只用于浏览；素材集（L1）补齐逐台内外参、时标与 IMU；训练集（L2）在同步、标定、码率、质检、标签上全部到位；评测集（L3）则在训练集之上，再加度量深度真值、置信度 mask、可复跑评测脚本、固定划分与下游实测举证。训练集回答"模型能不能学"，评测集回答"学得对不对、能不能泛化"。两者职责不同，一旦混用，两个答案同时失真。

隔离的第一层是设备隔离。同一台设备采集的数据，传感器噪声、畸变、佩戴姿态、曝光习惯高度相关。若训练与评测共用硬件，模型学会的可能是"这台设备的指纹"而非任务本身。所以评测批必须用与训练集隔离的独立设备，佩戴位姿重复性还要单独记录。

第二层是场景隔离。评测集的场景清单固定，且与训练集不重叠。这不是苛刻，而是防"见过这道题"：模型在训练里见过同类场景、同类操作，评测分数再高也证明不了泛化。海鲜加工、非遗技艺这类长尾子集单独计分，正是为了量化模型面对"没见过的题"时的真实水平。

第三层是存储隔离。评测数据以只读冻结副本归档、附校验和，交付走独立隔离环境。冻结意味着不能补数据、不能替换样本；一旦发现泄漏，唯一处置是整批冻结重采，不接受修补。这种"不近人情"，恰恰是评测可信度的来源。

配套机制与隔离墙同等重要：全量逐帧检验加第三方复核，固定失败子集单独计分，评测脚本可复跑、分母可重算，最终以"下游实测通过率"而非自报分数作为验收依据。

隔离不是成本，而是评测公信力的前提。EGO-S2 把"物理隔离"写进技术口径而非事后补救，原因很简单：一份会漏题的成绩单，比没有成绩单更危险。
